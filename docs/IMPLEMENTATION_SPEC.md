# IO-MF Phase 1 implementation specification

**Status** Draft for review. Phase 1 covers manuscript analysis, architecture, traceability and acceptance criteria. Training, experiments, firmware and dashboard work follow plan review.

**Source** Monika Jascinth K and Deepa S, *Deadline-Constrained Information-Aware Modality Activation for Embedded Multisensory Inference*. References below use the physical PDF page index, including the title page. The workspace contained no original source, checkpoints, datasets or results. The manuscript's Code and Data Availability statement has a placeholder for the repository. The plan therefore assumes independent reconstruction unless the original artifacts are supplied.

## Proposed reference implementation

- Start with UCI-HAR. Use its official subject-independent train/test partition and reserve whole official training subjects for validation. Read the released 128-sample inertial windows at 50 Hz (2.56 seconds, 50% overlap). Keep aligned subject, label and window identifiers across accelerometer and gyroscope inputs. Fit normalization and any imputation or priors only on model-fitting subjects. Keep the split fixed across seeds. The accelerometer is mandatory and gyroscope optional.
- Train one mask-aware host per seed. Each inertial branch has three 1D convolution blocks with widths 32/64/128 and kernels 5/5/3, each with batch normalization, ReLU and max pooling. Global average pooling yields 128 features. Later low-dimensional streams use a two-layer ReLU MLP with widths 64/128. Concatenate embeddings in fixed modality order and append the binary availability mask. Use zero vectors for inactive slots after normalization. Apply independent whole-stream dropout of 0.20 to optional modalities during host training, and 0.30 dropout before the single linear classifier. The primary stream always remains present. Compute softmax for inference.
- Use Adam with initial learning rate 0.001, weight decay 0.0001, batch size 64 and at most 100 epochs. Select host checkpoints by validation macro-F1 with patience 10. Freeze host parameters and buffers and run the host in evaluation mode during probe fitting and all inference. Fit probes on training subjects only. The inertial probe uses the first convolutional block followed by global pooling and linear projection to 128 features. Later low-dimensional probes use a single projection and nonlinear activation. Keep probe checkpoints separate from the host.
- Run at batch size one for timing. Record exact and probe entropy, candidate utility and eligibility, full encoder commits, stop reason and costs. A raw window can be available to a probe even when its full encoder is skipped. Track acquisition separately from encoding.

| §4.1, Eqs. 3–6, PDF p. 7 | src/controllers/iomf.py | Exact gain is current exact entropy minus exact candidate entropy. The runtime score uses current exact entropy minus candidate probe entropy minus lambda times encoder cost. Rank by score and require strict positivity. |

| §§4.4–4.5, Eq. 16 and Algorithm 1, PDF pp. 9–10 | src/controllers/iomf.py | Encode primary set, then score all remaining candidates at each active set. Stop when the set is exhausted or the best score is zero or negative. Return the last exact distribution and its argmax. |
| §4.6, Eq. 17, Algorithm 2 and Theorem 1, PDF pp. 10–11 | src/controllers/iomf_d.py | If mandatory upper time a0 exceeds deadline B, return infeasible before invoking encoders. Otherwise start with r = B - a0. In fixed order admit a probe only if q + u <= r and q + leader reservation <= r. Debit q, select the best feasible strictly positive leader using fixed ties, then debit u on commit and refresh the exact prediction. On commit remove all candidates probed that round. Candidates skipped by admission remain eligible next round. With no leader return the current exact prediction. |

| §5, Theorem 2, Corollary 1, Eq. 21 and Theorem 3, PDF pp. 11–15 | tests/; experiments/probe_fidelity.py; experiments/timing.py | With K0 optional streams Algorithm 1 permits at most K0 commits and K0(K0+1)/2 candidate evaluations. | §6.1 and Table 2, PDF pp. 15–17 | src/preprocessing/; training/; configs/; src/baselines/ | Lock subject splits, channel mappings and training protocol. For later dataset work, §6.1 specifies OPPORTUNITY S1–S2 for training, S3 for validation, S4 for testing. PAMAP2 uses subjects 1–6 for training, 7 for validation and 8–9 for testing, excludes optional activities and masks transition/invalid labels. In the cross-device study the paper uses OPPORTUNITY, STM32F746G-DISCO (INT8 with FP32 controller arithmetic), Raspberry Pi 4 and Intel NUC 11 Pro. ESP32-S3/Wokwi is a proposed simulator target. Label modeled timing, simulator timing and physical measurements separately. Algorithm 2 uses a0 for mandatory inference, q for probe plus temporary fusion/head and u for full encoding plus exact refresh, with control and scheduling overhead assigned to the bounds. Keep these timing bounds separate from the utility costs C. Simulation alone supplies neither board energy measurements nor physical WCET certification.

## Acceptance criteria

**Phase 1 review**

- Confirm the source manuscript and traceability, resolve Algorithm 2's scheduling interpretation, and approve the scope and order of implementation.
- Identify original artifacts or explicitly approve reconstruction. Record any unresolved experimental settings as named configuration decisions before collecting research results.

**Implementation and evaluation after review**

- Dataset checks prove that train, validation and test subjects are pairwise disjoint, train-only transforms are applied everywhere, modalities align per window, and split manifests reproduce across runs.
- Unit tests cover entropy on uniform and peaked distributions, negative realized gain, heterogeneous utility costs, exact-zero early exit, deterministic ties, empty optional sets, cache isolation and one full-encoder call per committed stream. Validate exact output against direct host inference with the same active set. Verify unchanged host parameter and buffer hashes after probe fitting and controller runs.
- Deadline tests cover infeasible mandatory work, exact-budget equality, admission and reservation rejection, scanning after a skipped candidate, discarded probed losers, absence of a positive leader and a multi-round commit trace. Budget debits reconcile exactly and residual time stays nonnegative. Use at least three optional streams in synthetic scheduling tests to exercise reservations and subsequent scans.
- A UCI-HAR smoke run trains a host, fits probes and evaluates both controllers, primary-only and static fusion using one frozen checkpoint. Subsequent research runs produce per-seed configurations, checkpoints, predictions, traces and metric summaries. Report fidelity as threshold agreement, ranking agreement where defined and mean absolute entropy-gain error. Report modeled costs, empirical timings and any actual energy measurements with their provenance. Derive metrics from recorded outputs.
